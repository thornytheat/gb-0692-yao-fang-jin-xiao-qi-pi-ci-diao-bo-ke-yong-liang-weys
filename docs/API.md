# 接口

`POST /api/run`：JSON中的csv文本，省略使用样例；或multipart字段file。最大5MB。

`POST /api/m1`至`POST /api/m7`：独立运行到指定模块，JSON结构同运行接口。

`GET /api/history`：历史批次。`POST /api/review`接收id、revision和decision（通过或退回）。`GET /api/evidence.csv`提供单一证据导出。

结构错误422，版本变化409，文件过大413；错误返回code与message。所有页面可从左侧七个模块入口访问。

`GET /api/runs/<id>`读取指定批次；页面与证据CSV通过run_id查询参数绑定批次，模块导航保留该参数。

`POST /api/revision`：同批号补录新修订，生成关联替代版本并自动切换当前执行方案。JSON字段：`csv`（省略走样例，也支持multipart的file字段）、`parent_id`（可省略）、`idempotency_key`（重试键，同键重复提交返回同一批次，不重复占库）。省略`parent_id`时按业务实体键指纹自动寻链，指纹不一致或无链返回409 `CHAIN`；显式提供`parent_id`表示承接意图，允许实体集合增减（消失的需求登记`released_holds`、消失或不足的批号登记`lost_holds`）。

`GET /api/chains/<chain_id>`：返回修订链全部版本（含各版复核结论）与当前执行方案ID。`POST /api/runs/<id>/activate`（JSON对象，可为`{}`）：在同链内切换当前执行方案，原版本内容与复核依据保持不变。

JSON请求体必须是对象，数组、标量、null、损坏JSON及错误上传字段返回400，且不运行默认样例。

## 修订替代规则

- 批次内容不可变：修订只在同链上新增版本，不覆盖旧批次，原复核结果与原占库依据始终可查。
- 同链以业务实体键指纹判定（库存按来源单据号、需求按需求单号），与文件顺序无关；批号可在修订中替换或消失。
- `version`列为修订号（正整数）。同键同修订号异值判`CONFLICT`隔离并拒绝覆盖；修订号倒退判`REV_STALE`隔离，维持已采信的最高修订，不倒扣。
- 父方案未发调拨按批号汇总为占用，在新方案M5分配前从最新可调拨量中预留；M3效期分层与整包装算法不变，不发生实际物流。
- 批号在新输入消失或最新库存不足以承接占用时登记`lost_holds`；旧需求单消失登记`released_holds`，占用释放。
- M7复核页面与接口提供原方案量、新方案净需求、未发占用承接、本版已分配与可用差额；M6对账增加占用承接与本版可用差额行，守恒差额为零。
